Type Arabic on Windows the way you already text. Write Arabizi (`mar7aba`, `3ala`, `2albi`) in any app and
Type3arabi turns it into the Arabic you meant, with the most likely word already picked.

اكتب بالعربيزي في أي برنامج على ويندوز، و«اكتب عربي» يحوّلها إلى العربية التي قصدتها.

## Download

## New in 1.1.3 — please update
- **Fixed: some apps froze on the first letter** (1.1.0 – 1.1.2). Apps that talk to keyboards the older way (IMM32) —
  such as Subtitle Edit 5 and other apps built with Avalonia, Qt 5, Java or SDL, and many games — could hang right after
  the first Arabizi letter: the word list stayed black, and Windows could show the "IME disabled" icon. Type3arabi kept
  re-checking where the word was, and in these apps each check counted as a new move. It now stops as soon as the word
  hasn't moved. Notepad, Word, browsers and Windows Search were not affected and work as before.
- **New test for these apps**: every release is now also checked in an IMM32 app (64- and 32-bit), not only in
  modern ones.

## Updating
**Installed Type3arabi from an MSI (1.0 or later)?** Run the 1.1.3 MSI, then **restart Windows**. Your settings and learned
words are kept. The restart matters: an app that is already open keeps the old keyboard until it is closed. That
includes an app that froze earlier, which may still be running in the background.

**Ever built Type3arabi yourself, or ran `regsvr32` on a preview build?** That can leave a per-user registry entry (a
"ghost" registration) that overrides the installed keyboard. Every app of that kind (often all 32-bit apps) then keeps
loading the old preview DLL, with its old bugs, whatever version you install. The MSI never creates these entries.
Check in PowerShell (no admin needed):

```powershell
$clsid = '{8A4B9277-1E2E-45E0-92A2-83FED833D8BF}'
"HKCU:\Software\Classes\CLSID\$clsid", "HKCU:\Software\Classes\WOW6432Node\CLSID\$clsid" | Where-Object { Test-Path -LiteralPath $_ }
```

No output: nothing to do. If it prints a path, remove it, then sign out and back in (or restart):

```powershell
"HKCU:\Software\Classes\CLSID\$clsid", "HKCU:\Software\Classes\WOW6432Node\CLSID\$clsid" | Where-Object { Test-Path -LiteralPath $_ } | ForEach-Object { Remove-Item -LiteralPath $_ -Recurse }
```

This removes only Type3arabi's per-user entries. The installed keyboard (registered for the whole PC) is untouched.
From a source checkout, `scripts\dev-uninstall.ps1` does the same plus a full cleanup.

## Install
1. Run the MSI. The page after the license lists what it adds. A restart is recommended at the end.
2. Press **Win+Space** and pick **Arabic · Type3arabi**, or press **Ctrl+Alt+A** (your own shortcut can be set in Settings).
3. Type `mar7aba` and press Space.

## What's in it
- A real Windows keyboard (TSF): one entry under Arabic, in every app.
- Steps aside by itself: the browser's address bar and password fields get plain Latin — no switching back and forth.
- Your word, already picked: Space inserts it, ↓ / click / mouse wheel pick another; Shift+Space keeps a word in Latin.
- Reads your dialect automatically: Levantine, Egyptian, Gulf, Iraqi, Maghrebi and MSA.
- ‎«اللّه»‎, «شكراً»‎ and Arabic punctuation ،‎ ؛‎ ؟‎ handled automatically.
- Diacritics editor (Tab): any mark on any letter, several letters at once, ready-made vowellings.
- Learns your choices, on this PC only; export/import them (`.t3learn`) or erase them.
- Settings app: every shortcut editable (shortcuts Windows already uses are refused, with the reason); light/dark.
- 100% offline: no account, no network, no telemetry. Privacy: https://type3arabi.com/privacy

## Known limitations
- Start menu search may add its own suggestion after your word (for example a whole sentence after «مرحباً»‎). That is Windows, not Type3arabi; pasting the word into Start shows the same.
- x64 Windows only (ARM64 later). Egyptian has little training data yet.
- Upgrading while apps use the keyboard finishes at the next restart.
